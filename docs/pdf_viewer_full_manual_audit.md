# PDF 뷰어 전체 동작/시각 점검 보고서

점검일: 2026-05-31  
대상: `digikey_scraper/datasheet_viewer.py`  
점검 방식: 합성 데이터시트를 실제 `DatasheetViewer`에 로드하고, 버튼/메뉴/감지/저장/AI 컨텍스트를 프로그램으로 직접 실행한 뒤 화면 캡처 확인

## 결론

전체 재구현까지 바로 갈 상황은 아니다.  
PDF 로딩, 렌더링, 필터, OCR, 표/핀맵 감지, 영역 저장, AI 컨텍스트 생성 같은 핵심 기능은 자동 구동 기준으로 동작한다.

하지만 **시각적 품질과 상태 관리에는 실제 사용자가 “정상 동작하지 않는다”고 느낄 수 있는 문제가 있다.**  
특히 검색 오버레이가 다른 페이지/다른 작업 상태에 남는 문제, 감지 패널이 열릴 때 Fit Width 재계산이 어색한 문제, 제목만 별도 후보로 잡히는 문제가 우선 수정 대상이다.

### P0-1. 검색 강조가 페이지/작업 상태를 따라 잘못 남음

상태: 해결됨

기존 증거:
- `05_shown_table_detection.png`에서 `Supply Voltage` 검색 강조가 표 감지 화면에도 남아 있다.
- 제목 영역에도 노란 검색 강조처럼 보이는 표시가 남아 혼란스럽다.

원인 추정:
- `_highlight_rects`가 페이지 번호와 묶여 있지 않다.
- 검색 후 다른 페이지로 이동하거나 감지를 실행해도 이전 검색 강조가 계속 오버레이에 포함된다.

사용자 영향:
- 사용자는 감지된 표 영역인지, 검색 결과인지 구분하기 어렵다.
- “표를 찾았는데 이상한 곳도 강조된다”고 느낀다.

수정 방향:
- 검색 결과를 `(page_index, rects)` 형태로 저장
- 현재 페이지와 검색 결과 페이지가 다르면 검색 오버레이 표시하지 않기
- `_detect_tables`, `_find_pinmap` 실행 시 검색 강조를 유지할지 끌지 명확한 정책 추가
- UI에 `검색 강조 지우기` 액션 추가

적용:
- `_highlight_page` 추가
- 검색 오버레이는 현재 페이지와 검색 결과 페이지가 같을 때만 그림
- 감지/핀맵 찾기 실행 시 검색 강조를 초기화

### P0-2. 감지 패널이 열릴 때 Fit Width 재계산이 어색함

상태: 해결됨

기존 증거:
- `05_shown_table_detection.png`에서 오른쪽 감지 패널이 열리자 문서가 왼쪽 영역 너비에 맞게 깔끔하게 재계산되지 않고 가로 스크롤이 생긴다.

원인 추정:
- `_refresh_region_panel()`에서 패널을 show한 직후 splitter 레이아웃이 안정되기 전에 `_refresh_image()`가 실행된다.
- Fit Width 계산 시 scroll viewport 폭이 패널 오픈 후 실제 폭과 다를 수 있다.

사용자 영향:
- 표 감지 후 PDF가 갑자기 잘린 것처럼 보인다.
- 감지 영역 오른쪽이 패널에 가려진 것처럼 보일 수 있다.

수정 방향:
- 감지 패널 표시 직후 splitter size를 명시적으로 설정
- 패널 show 후 `QTimer.singleShot(0, self._refresh_image)`로 레이아웃 안정 후 재렌더링
- Fit Width 계산 시 현재 splitter/viewport 실제 폭을 기준으로 캐시 무효화

적용:
- 감지 패널 표시 시 splitter size 보정
- Fit Width/Fit Page 상태에서 `QTimer.singleShot(0, ...)`로 재렌더링

### P0-3. 제목/섹션 헤더가 별도 감지 후보로 표시됨

상태: 해결됨

기존 증거:
- `05_shown_table_detection.png`에서 `ABSOLUTE MAXIMUM RATINGS` 제목이 `#2` 후보로 표시된다.

원인 추정:
- PDF word 기반 감지와 semantic score가 제목/헤더 텍스트도 유용한 섹션으로 점수화한다.
- 실제 표 본문과 제목 context를 분리하지 못한다.

사용자 영향:
- 후보 목록에 실제 저장/분석할 표가 아닌 제목만 나타난다.
- 사용자가 제목 후보를 저장하거나 AI 분석 대상으로 선택할 수 있다.

수정 방향:
- 후보 텍스트가 1~2줄이고 숫자/단위/컬럼 구조가 부족하면 region 후보에서 제외
- 섹션 제목은 region 후보가 아니라 `context title`로만 사용
- `_nearest_text_above_region()` 결과와 후보 영역을 분리

적용:
- 제목만 있는 후보를 제거하는 후처리 추가
- PDF word 기반 표 감지에서 실제 테이블 헤더 행부터 crop 후보를 만들도록 보정

### P1-1. 감지 후보 패널의 정보가 짧게 잘려 판단이 어렵다

증거:
- 후보 목록에 `#1 · 열 · 5.52 · 703x315...`처럼 표시되어 정확히 어떤 후보인지 바로 파악하기 어렵다.

사용자 영향:
- 사용자가 후보를 선택하기 전에 충분한 정보를 못 본다.

수정 방향:
- 후보 항목에 `전기특성표`, `핀맵`, `섹션 제목`, `오탐 가능` 배지 표시
- score보다 타입/텍스트 첫 줄을 우선 표시
- 선택 후보 미리보기 영역을 조금 키우거나 접이식으로 변경

### P1-2. 검색 오버레이와 감지 오버레이가 동시에 보이면 화면이 복잡하다

증거:
- 검색 강조, 감지 박스, 후보 라벨이 한 화면에 동시에 표시된다.

사용자 영향:
- 무엇이 검색 결과이고 무엇이 감지 후보인지 헷갈린다.

수정 방향:
- 감지 실행 시 검색 오버레이를 자동으로 숨기거나, 검색 강조를 더 얇고 투명하게 표시
- 오버레이 레이어별 색상 범례 제공

### P1-3. 선 없는 표 후보가 넓게 잡히는 경향이 있다

증거:
- 자동 점검에서 선 없는 표 후보가 `(70, 10, 995, 478)`처럼 제목까지 넓게 포함됐다.

사용자 영향:
- 영역 저장/AI 분석 시 필요한 표보다 큰 영역이 들어간다.

수정 방향:
- PDF 텍스트 row grouping에서 섹션 제목과 본문 표를 분리
- 표 헤더(`Parameter/Min/Typ/Max/Unit`) 시작점 기준으로 위쪽 padding 제한
- 제목은 context로만 붙이고 crop 영역에서는 제외

### P2-1. 툴바가 기능 대비 너무 밀집되어 있다

증거:
- 필터, 확대, 프리셋, 검색, OCR, Gemma, 감지, AI 범위, AI, 오버레이가 모두 상단에 몰려 있다.

사용자 영향:
- 화면 폭이 좁으면 버튼이 잘리거나 찾기 어렵다.

수정 방향:
- 기본 모드: 검색, 감지, 영역 저장, AI 질문만 노출
- 고급 모드: 필터, OCR, 오버레이 세부 토글, 수동 영역, 자동 AI 검증 이동

### P2-2. OCR 언어 설정 UI가 없다

현재 상태:
- 내부 설정에는 `ocr_lang`이 있지만 UI에서 바꾸기 어렵다.

수정 방향:
- OCR 메뉴에 `eng`, `kor`, `eng+kor` 선택 추가

### P2-3. 실제 Gemma API 호출은 자동 점검에서 검증하지 않았다

현재 상태:
- 프롬프트 생성, 컨텍스트 구성, worker 경로는 확인했다.
- 실제 네트워크/API 응답은 키와 네트워크에 의존하므로 별도 수동 검증 필요.

수정 방향:
- API 키가 있을 때 `짧은 샘플 질문`으로 실제 호출 smoke test 추가
- 실패 원인: 키 없음, quota, 네트워크, 응답 파싱 실패를 분리 표시

## 재구현 필요성 판단

현재 상태에서 **전체 PDF 뷰어를 처음부터 다시 구현하는 것은 비효율적**이다.

이유:
- 렌더링, 필터, 감지, 저장, OCR, AI 컨텍스트의 핵심 기능은 동작한다.
- 문제는 주로 오버레이 상태 관리, 레이아웃 갱신, 후보 후처리 품질이다.
- 따라서 전체 재작성보다 아래 순서의 부분 리팩터링이 맞다.

## 수정 우선순위

### 1순위

1. 검색 강조를 페이지별 상태로 분리하거나 페이지 이동/감지 시 초기화
2. 감지 패널 show 후 Fit Width 재계산 안정화
3. 섹션 제목을 감지 후보에서 제외하고 context로만 사용

### 2순위

4. 검색 오버레이와 감지 오버레이 동시 표시 UX 정리
5. 후보 목록 배지/타입 표시 개선
6. 선 없는 표 crop 범위 축소

### 3순위

7. 툴바 단순화
8. OCR 언어 선택 UI 추가
9. 실제 Gemma 호출 smoke test 추가

## 권장 작업 단위

1. `OverlayState` 분리
   - 검색 오버레이, 감지 오버레이, 수동 영역을 별도 상태 객체로 관리

2. `RegionCandidate` 모델 도입
   - `box`, `score`, `kind`, `source`, `text`, `context_title`을 함께 보관

3. 패널/렌더링 갱신 순서 정리
   - 패널 show/hide, splitter resize, pixmap cache clear, refresh 순서를 명확히 분리

4. 감지 후처리 강화
   - 페이지 전체 후보 제거는 이미 적용됨
   - 제목 후보 제거와 표 crop 축소를 추가해야 함

적용 내용:
- 감지 오버레이 라벨을 단순 점수에서 `#번호 종류 신뢰도 점수` 형식으로 변경했다.
- 종류 태그는 이미지 저장에서도 깨지지 않도록 ASCII 기반 `ELECT`, `PINS`, `PKG`, `THERM`, `ABS`, `SECTION`으로 표시한다.
- 전기특성, 핀, 패키지, 열 정보, 일반 섹션 후보의 박스 색상을 다르게 표시한다.
- 오른쪽 감지 후보 패널과 PDF 오버레이가 동일한 분류 기준을 사용하도록 정리했다.

검증:
- 생성 이미지: `docs/pdf_viewer_audit/08_overlay_visual_labels.png`
- 전기특성 표가 `ELECT HIGH` 라벨과 녹색 박스로 표시되는 것을 확인했다.
- 후보 패널에 `Electrical`, 신뢰도, 영역 크기, 텍스트 미리보기가 표시되는 것을 확인했다.
